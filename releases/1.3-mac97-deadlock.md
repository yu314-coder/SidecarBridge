# macOS 1.3 (97): remote-input authorization deadlock

Two live process samples of installed Mac 1.3 (96), PID 63309, confirmed the same cycle:

1. Main was blocked acquiring AuthorizationGeneration's recursive lock in a LAN command callback.
2. The serial remote-input queue held that lock across RemoteInputController.handle.
3. Its input-source operation synchronously waited for main via MainQueueExecutor.

Physical footprint was approximately 122 MB. This evidence identifies a lock-order bug, not RAM exhaustion.

## Fix

AuthorizationGeneration.onMain dispatches before acquiring the lock and revalidates the captured generation after reaching main. The remote input pipeline uses separately gated phases for TIS input-source selection, toggle confirmation, and AX text insertion. Clipboard fallback stays on the worker queue. Normal Quartz events remain on the serial worker queue. No pointer geometry, video settings, pairing credential rules or revocation policy was weakened.

Each privileged phase still checks the original authorization generation. Revocation between phases causes subsequent work to be discarded. Input completions no longer run inside the gate.
