# iOS/iPadOS 1.3 (19): keyboard placement correction

The build 18 component tests did not catch full viewer safe-area interaction. A full-height viewer with a bottom safe-area inset could place the keyboard beyond the visible bounds.

## Fix
- Anchor the keyboard as a bottom overlay; leave the video/input coordinate space unchanged.
- Explicitly size and clip the scrolling key area, keeping mode and Clear/Hide controls outside it.
- Leave bottom clearance for the home indicator and hide the gesture hint while typing.
- Clear the hidden text receiver's UIKit input assistant groups so its shortcut strip does not cover the custom keyboard.
- Added a Debug-only layout launch flag using the real viewer without starting network discovery. Release builds cannot enable it.
